## Summary

Build a Windows desktop application for English learning with four core modules: Speaking (Shadowing + Teleprompter), Writing (AI Evaluation), Vocabulary (Spaced Repetition), and Clipboard Capture. The app is built with Tauri v2 (Rust backend + React/TypeScript frontend), stores all data locally in SQLite, and integrates Gemini 2.0 Flash for AI-powered evaluation and content processing. All research decisions are resolved in [research.md](./research.md).

---

## Technical Context

**Language/Version**: TypeScript 5 (React 18 frontend) + Rust 1.77 stable (Tauri backend)

**Primary Dependencies**: Tauri v2, React 18, Vite 5, Tailwind CSS v3, Redux Toolkit, TanStack Query v5, rusqlite, reqwest, arboard, tauri-plugin-sql, tauri-plugin-store, tauri-plugin-clipboard-manager

**Storage**: SQLite local database via rusqlite (Rust) + tauri-plugin-sql (frontend CRUD); FTS5 virtual table for full-text search; BLOB columns for semantic embeddings

**Testing**: Vitest + React Testing Library (frontend); cargo test (Rust backend)

**Target Platform**: Windows 10/11 desktop (requires WebView2 runtime — pre-installed on Windows 11)

**Project Type**: Desktop application (Tauri)

**Performance Goals**: Clipboard popup appears within 2 seconds of Ctrl+C; STT + accuracy score returned within 10 seconds for 60-second recordings; knowledge library search returns within 1 second for 10,000 items

**Constraints**: Core features (SRS review, flashcards, teleprompter display, saved content browse) work offline; YouTube playback and Gemini API calls require internet; single-user, no cloud sync

**Scale/Scope**: Single user; local SQLite database; supports 10,000+ saved content items; 1,000+ vocabulary entries

## Implementation Phases

### Phase 1 — Project Scaffold & Core Infrastructure

**Goal**: Working Tauri app shell with database, navigation, and settings.

1. Initialize Tauri v2 + React + TypeScript project with Vite and pnpm
2. Install and configure all dependencies (see quickstart.md)
3. Set up SQLite with migration 001 (full schema from data-model.md)
4. Create main TabBar navigation (Speaking / Writing / Vocabulary / Clipboard / Settings)
5. Implement Settings screen with Gemini API key input stored via tauri-plugin-store
6. Set up Redux store and TanStack Query provider
7. Verify `pnpm tauri dev` runs successfully on Windows

---

### Phase 2 — Vocabulary SRS Module

**Goal**: Add, review, and schedule vocabulary cards using SM-2.

1. Implement `srs.rs` — SM-2 algorithm in Rust with unit tests
2. Implement Tauri commands: `add_vocabulary_entry`, `get_due_cards`, `submit_review_rating`, `start_review_session`, `end_review_session`
3. Build `AddWordForm` component (word, phonetics, meaning, example, notes, tags)
4. Build `Flashcard` component (front/back flip, TTS pronunciation via Web Speech API)
5. Build `ReviewSession` component (queue management, 4 rating buttons, session summary)
6. Wire TanStack Query hooks for vocabulary CRUD and due-card queries
7. Display due card count badge on Vocabulary tab icon

---

### Phase 3 — Writing AI Evaluation Module

**Goal**: Submit writing passage, receive structured Gemini AI evaluation.

1. Implement `gemini.rs` HTTP client service (Gemini 2.0 Flash API)
2. Implement `evaluate_writing` Tauri command with mode-specific system prompts (IELTS/TOEIC/Aptis/General)
3. Build `WritingEditor` component (textarea, word count display, evaluation mode selector)
4. Build `EvaluationReport` component (score cards, grammar corrections, improvement suggestions)
5. Handle loading state, error state, and retry logic in UI
6. Persist submission history to SQLite; display past submissions list

---

### Phase 4 — Speaking: Teleprompter Module

**Goal**: Paste text, record while text auto-scrolls, receive accuracy evaluation.

1. Implement `save_recording` Tauri command — sends audio to Gemini for STT transcription, computes accuracy score via text diff
2. Build `TeleprompterDisplay` component (CSS scroll animation, font size/color/background customization)
3. Build `RecordingControls` component (MediaRecorder API hook, start/stop/playback controls)
4. Build `AccuracyScore` component (word-by-word diff visualization: green=correct, red=missing, orange=mispronounced)
5. Implement `create_teleprompter_session` command to persist display config

---

### Phase 5 — Speaking: Shadowing Module

**Goal**: YouTube video + imported SRT subtitles + repeat range + record + accuracy score.

1. Implement YouTube IFrame API wrapper (`youtubePlayer.ts`) with 250ms polling for `getCurrentTime()`
2. Build `VideoPlayer` component (YouTube embed, play/pause/seek controls, timeline display)
3. Build `SubtitleEditor` component (list of cues, inline text editing per cue, save button)
4. Build `RepeatRangeControl` component (Start/End time pickers, Loop Mode toggle)
5. Implement `import_subtitles` Tauri command (SRT parser in Rust: parse timestamp + text)
6. Wire `create_video_session` command; sync subtitle display to video `currentTime`

---

### Phase 6 — Clipboard Capture Module

**Goal**: Background clipboard monitoring, Save popup, tagging, knowledge library search.

1. Implement `clipboard_watcher.rs` — Rust background thread polling `arboard` at 500ms; filter: text-only, ≥10 chars, changed from last
2. Emit `clipboard:changed` Tauri event to frontend
3. Build `SavePopup` overlay component triggered by `clipboard:changed` event (Save/Ignore buttons, category selector, tag input)
4. Implement `save_captured_content` Tauri command
5. Implement `search_captured_content` command with SQLite FTS5 + metadata filtering
6. Build `ContentLibrary` component (search bar, filter sidebar by tag/category/date, results list)
7. Implement optional `process_content_with_ai` command (Gemini: extract vocabulary, collocations, idioms, summary)

---

### Phase 7 — Polish & Cross-Feature Integration

**Goal**: Production-quality UX, error handling, performance verification.

1. Error boundaries on all tabs; user-friendly messages for API failures and microphone permission denial
2. Offline indicator — gracefully disable AI-dependent buttons when no connectivity
3. Duplicate vocabulary word detection with merge/update option
4. SRS backlog cap — show maximum 20 overdue cards per session to prevent overwhelm
5. Keyboard shortcuts: Space = flip flashcard; 1/2/3/4 = rate Again/Hard/Good/Easy
6. App icon, window title bar, system tray icon for clipboard monitoring background mode
7. Performance verification: search 10,000 content items returns results <1 second

## Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| STT engine | Web Speech API (real-time) + Gemini (post-recording) | Zero-cost real-time feedback; high-accuracy final score |
| SRS algorithm | SM-2 in Rust | Battle-tested, ~50 lines of code, sufficient for v1 |
| Clipboard monitoring | Rust thread + arboard polling at 500ms | Avoids complex OS hook FFI; negligible CPU cost |
| AI call routing | All Gemini calls from Rust backend | API key never exposed in frontend JavaScript bundle |
| Full-text search | SQLite FTS5 | No external search server; offline; fast for 10k items |
| Video playback | YouTube IFrame API | Streaming only; no storage; no YouTube ToS violation |
| TTS | Web Speech Synthesis API | Built-in Chromium API; Windows neural voices; zero cost |
| State management | Redux (UI/transient) + TanStack Query (SQLite/server) | Clear boundary; TanStack handles cache invalidation |
